# 스마트스토어 자동 추출 v2026-10-28.3

## 확인한 원인과 아직 확인하지 못한 부분

사용자 Windows 크롬에서는 상품·이미지가 표시되고 직접 선택도 작동하지만 기존 상품 영역 일치가 0이었다. 따라서 페이지 DOM 전체에 접근하지 못한 것으로 보기는 어렵고, **자동 후보를 선정하는 단계가 화면의 상품을 포함하지 못하는 상태**로 좁힐 수 있다. 이미지 5개는 로드된 IMG 수이며, 모두 상품 사진이라는 뜻은 아니다.

코드에서 확인한 병목은 다음과 같다.

- 기본 상품 탐색이 일부 래퍼/선택자에 한정돼 있었다.
- 일반 제목을 읽는 대안도 usable OG 메타데이터가 있을 때만 동작했다.
- 이미지 후보도 같은 래퍼 또는 og:image와 일치해야 했다.
- 평점과 리뷰 수의 일반적인 상품 요약 문맥을 읽지 않았고, 리뷰 수 필드 자체가 없었다.

이번에도 제공된 실제 URL에 일반 요청했지만 프록시 CONNECT 단계에서 403으로 실패했다. 실제 네이버 HTML은 확보하지 못했다. 그러므로 해당 상품에서 정확히 어떤 태그/메타 조건이 실패했는지, 이번 변경이 실제 페이지에서 성공하는지는 **미검증**이다. 사용자 제공 상품명·가격·평점·리뷰 수는 코드의 예외 조건이나 고정 반환값으로 사용하지 않았다.

## 자동 추출 경로

기존 상품 DOM과 공개 메타데이터를 유지하면서, 네이버에 다음 대안을 추가했다. 비공개 상태·API·로그인 정보는 읽지 않고 DOM만 조사한다.

1. h1~h4/접근성 제목과 큰 글씨의 표시 텍스트에서 상품명 후보를 찾는다. 특정 클래스 이름이나 main/#content 존재를 필수로 하지 않는다.
2. 후보 주위에서 판매가 문맥, 구매/장바구니 컨트롤, 로드된 큰 상품 사진, 평점/리뷰 요약을 함께 조사한다. 문서 전체를 상품 설명으로 복사하지 않고, 조건을 충족하는 작은 상품 영역을 선택한다.
3. 구매 컨트롤이 일반적이지 않아도 페이지 제목과 표시 제목이 일치하거나, 판매가·사진·평점/리뷰 요약이 함께 있으면 별도 경로를 사용할 수 있다.
4. 가격은 판매가/할인가/상품가격 문맥과 강조 표시를 읽는다. 숫자와 ‘원’이 다른 요소로 나뉜 경우도 처리한다. **최저 금액이나 가장 큰 숫자를 판매가로 간주하지 않는다.** 카드·쿠폰·배송비·적립·포인트·할부·혜택 문맥과 취소선 원가는 제외한다. 비슷한 판매가 후보가 충돌하면 미확인으로 남긴다.
5. 추천·광고 문맥, 다른 상품 링크, 계정 헤더·입력창·작성 중인 편집 영역을 제외한다. 복수 상품 영역이 경쟁하면 임의로 확정하지 않는다. 일반 휴리스틱이라 모든 사이트 레이아웃에서 무오류를 보장하지 않는다.

쿠팡은 기존 전용 요소와 별도 경로를 유지한다. 리뷰 본문은 두 플랫폼 모두 현재 열린 리뷰 영역에서만 읽는다.

## 이미지·리뷰·옵션 구분

- **대표 이미지**: 상품 영역/근접 배치의 큰 현재 표시 사진을 후보로 선택한다. 링크된 다른 상품·외부 광고·프로모션 이미지를 제외한다.
- **추가 이미지**: 같은 상품 갤러리의 현재 표시된 추가 사진을 구분한다.
- **상세페이지 이미지**: 기존 상세 영역 또는 ‘상품 상세설명’ 등 명시적 상세 구역 안의 표시 사진을 구분한다. 화면 밖/미로드 이미지를 자동 스크롤하거나 새 URL로 요청하지 않는다.
- `images` URL 배열을 유지하고 `imageAssets`에 분류와 신뢰 상태를 추가했다. 선택 해제된 이미지 기록은 가져오기 때 제외한다. 저장 후 URL이 로컬 경로로 바뀌어도 `originImageUrl`로 원본 분류를 연결한다. 분류는 후보이며 사용 허락이나 선택 옵션 일치의 증거가 아니다.
- **평점**, **전체 리뷰 수**, **가져온 구매평 본문 수**는 서로 다른 항목이다. 전체 리뷰 수가 크다고 그만큼 본문을 확보했다고 표시하지 않는다.
- 구매평은 선택된 리뷰 탭/표시된 리뷰 제목과 정렬 컨트롤 등 열림 단서가 있는 영역에서만 읽는다. 명시적 본문 요소 또는 날짜·별점이 있는 리뷰 카드의 표시 문단을 사용한다. 작성자·선택 옵션·도움/신고/작성 안내는 본문과 분리한다. 구조가 불명확하면 빈 값으로 유지하며 구매 인증 자체는 확인하지 않는다.
- 네이버 옵션은 확인된 상품 영역 안의 이름 있는 네이티브 선택 컨트롤에서 실제 선택 상태를 읽을 때만 채운다. 임의의 aria-selected나 탭 이름을 옵션으로 채우지 않는다. 그 외 옵션은 미확인이다. 모든 유형의 커스텀 옵션을 지원하는 것은 아니다.

## 출처와 신뢰 상태

각 항목에 기존 DOM/공개 메타데이터/상품 영역/판매가 문맥/상품 요약/열린 리뷰/선택 컨트롤/수동 보완의 경로를 표시한다.

- **복수 단서 일치 · 원본 확인 필요**: 여러 DOM 단서가 일치했다. 공식 API·플랫폼·제조사의 독립 검증 완료가 아니다.
- **후보 · 원본 비교 필요**: 추출했지만 대응 관계나 문맥을 추가 확인해야 한다.
- **사용자 보완 · 자동 수집 아님**: 직접 선택/입력한 값이다.
- **미확인**: 근거가 부족하거나 충돌해 채택하지 않았다.

**자동 추출 당시** 상품명·가격·대표 이미지 결과는 따로 기록한다. 나중에 직접 선택해 채웠다고 자동 결과를 성공으로 바꾸지 않는다. 이전 버전 진단에 이 기록이 없으면 성공/실패를 새로 만들어 표시하지 않는다.

## Windows에서 자동 결과 재검증

1. 실행 창에서 Ctrl+C로 종료하고 기존 자료를 백업한다. 이번 브랜치는 이전 Windows 실행기와 진단 기능을 포함해 보존한다. 기존 작업 폴더/자료를 삭제하지 않는다.
2. 수정 파일을 반영한 뒤 **처음 설치하기.cmd → 쇼핑클립 시작하기.cmd**로 재빌드·재실행한다. 의존성 변경은 없다.
3. http://127.0.0.1:3100/products/browser 에서 **2026-10-28.3**을 확인한다. 기존 즐겨찾기는 자동 갱신되지 않으므로 삭제하고 새로 등록한다.
4. 실제 상품의 제목·판매가·대표 사진이 보이는 위치에서 실행한다. **직접 선택/직접 입력 없이** 자동 결과를 먼저 기록한다. 제보 기대값과 비교는 사용자가 실제 화면을 보며 수행한다.
5. 자동 결과의 대표/추가/상세 분류와 출처·신뢰 상태를 확인한다. 리뷰 탭을 열기 전에는 리뷰 수가 있어도 본문이 0개일 수 있다.
6. 리뷰 탭을 직접 열고 본문이 표시된 뒤 **현재 페이지 다시 읽기**로 자동 본문 결과를 확인한다. 추출기는 탭을 클릭하거나 리뷰 페이지를 넘기지 않는다.
7. 실패하면 **개인정보 없는 진단 파일 저장**으로 `clipforge-diagnostic.json`을 저장한다. 제목 후보·표시 제목 수·통화 표시 요소·구매 컨트롤·상품 영역·영역 충돌·혜택 금액 제외·이미지 호스트/범위 제외·리뷰 열림 상태로 원인을 더 좁힌다.

진단 파일에는 수치·플랫폼·상품번호·버전·정해진 경로/상태만 들어 있다. HTML, 제목/가격/리뷰 원문, 이미지 URL, 작성자, 쿠키, 토큰을 저장하거나 자동 전송하지 않는다. 상품 자료 파일과 진단 파일은 다르다. 직접 선택은 예외 상황의 보조 수단으로 유지하지만 자동 수집 성공 검증에는 사용하지 않는다.

## 검증 범위

예제 DOM 테스트는 메타데이터·기존 선택자·클래스 없이 서로 다른 상품명·가격을 자동 추출하고, 혜택 금액·추천·광고·가격 충돌·이미지 분류·평점/리뷰 수·탭 열림·옵션 미확인·수동 결과 분리를 확인한다. 이 결과를 실제 네이버·쿠팡 운영 페이지 또는 Windows 검증 완료로 바꾸어 표시하지 않는다.
