# 브랜드스토어 이미지 주소·열린 자료 영역 진단 (2026-10-28.5)

## 실제 첨부 파일로 확인한 사실

사용자 제공 `clipforge-diagnostic (1).json`을 직접 확인했다.
상품 12379874471, 버전 2026-10-28.4, 문서 complete, 최상위 문서,
iframe 0개, 상품명·가격 자동 성공, 대표 이미지 자동 실패였다.
화면에 로드된 이미지 2개는 주소 검사에서 모두 제외되었고 영역 검사에서 제외된 이미지는 0개였다.
상세와 리뷰 표지는 각각 BUTTON이며 LI → UL → DIV 안에 있었다.
둘 다 controls/fragment가 없었다. 기존 selected:false는 **속성 없음과 명시적 false를 구분하지 않았다.**
이 진단만으로 버튼이 비활성 탭이었다고 결론 내릴 수 없다.

`imageHostRejected`는 이름과 달리 기존 코드에서 URL 형식·프로토콜·인증 쿼리 등 검사 실패도 합산했다.
첨부 파일에는 실제 이미지 호스트·주소 검사 사유가 없어 두 이미지가 왜 제외됐는지는 확정할 수 없다.
특히 화면 이미지 2개가 모두 실제 상품 이미지라는 것도 파일만으로는 확인할 수 없다.

실제 상품 URL에 일반 HTTPS 접근을 시도했지만 이 실행 환경의 CONNECT 프록시가 403으로 거부했다.
상품 페이지의 HTML을 받지 못했다. 이것은 사용자의 브라우저에서 사이트가 차단되었다는 뜻이 아니다.

## 변경

### 이미지 주소

- 북마클릿, 자료 파일 파서, 이미지 저장에 하나의 순수 URL 검사 함수를 사용한다.
- 네이버 직접 주소는 기존의 정확한 `shop-phinf.pstatic.net`, `shopping-phinf.pstatic.net`만 허용한다. 임의의 `*.pstatic.net`이나 외부 판매자 호스트를 일괄 허용하지 않는다.
- `https://search.pstatic.net/common[/]?src=...`는 src가 위 CDN의 안전한 HTTPS 주소 한 개일 때 **네트워크 호출 없이 내부 주소로 정규화**한다. 중첩 래퍼, 외부/로컬 주소, 인증 쿼리는 거부한다.
- type/w/h/width/height/quality/q 같은 크기 조절 쿼리를 지원하며 값 자체는 진단에 기록하지 않는다.
- HTTPS·인증 정보·포트·fragment·민감 쿼리 조건을 공통 적용한다. URL을 허용해도 상품 이미지 영역 검사는 별도로 통과해야 한다.
- 저장 단계의 공개 이미지 리다이렉트는 최대 2회, 매 단계 동일한 CDN 목적지 검사를 통과해야 한다. 자동 따라가기는 끄고 쿠키/인증 헤더를 보내지 않는다. 403/429/로그인 화면은 우회하지 않는다.
- 실제 이미지 바이트·형식·크기 검사는 유지한다. 브라우저 currentSrc와 src의 차이는 srcset 등에서도 생기므로 리다이렉트 이력이라고 주장하지 않는다.
- 진단에 알려진 호스트 이름이 나온다는 것과 수집 허용은 별개이다. phinf/storep/dthumb/Apple CDN은 진단용 고정 분류에만 있고 새로 허용하지 않았다. 실제 주소를 확인하지 않고 도메인을 추측해 허용하지 않았다.

### 상세·구매평

- selected/aria-controls 외에 버튼 조상 최대 4단계의 형제 영역에서 표시된 내용의 근거를 찾는다. body 전체를 상세·리뷰 영역으로 취급하지 않는다.
- 상세는 명확한 제품 사양 키 2개 이상의 표 또는 충분한 길이의 공개 itemprop=description이 있는 경우에만 후보로 삼는다.
- 리뷰는 날짜·평점·표시된 본문을 가진 카드와 리뷰 정렬 컨트롤이 함께 있어야 한다. 독립 후보가 여러 개라면 확정하지 않는다.
- 버튼만 있거나 selected 같은 클래스만 있거나 평점 요약만 있는 경우는 열린 구매평의 증거가 아니다. 숨겨진 영역과 다른 상품 링크가 섞인 후보도 사용하지 않는다.
- 평점, 전체 리뷰 수, 실제 수집한 본문은 별도 필드다. 리뷰 본문 수를 전체 리뷰 수로 대체하지 않는다. 충돌하는 전체 리뷰 수는 미확인으로 남긴다.
- reviewMatches는 이번 버전부터 확인된 리뷰 영역 안의 명시 본문 요소와 구조 기반 본문 후보를 함께 센다. 실제 저장된 본문 수는 visibleReviews다.
- 후기 사진, 광고, 추천 상품 제외와 대표/추가/상세 이미지 구분은 유지한다.
- 사진/문단에 의미 있는 관계가 없으면 계속 미확인이다. 모든 브랜드스토어 구조 지원을 뜻하지 않는다.

### 구조 진단

- 이미지별 URL 실패 사유: host, protocol, credentials, port, fragment, sensitive_query, wrapper, invalid.
- 호스트는 고정된 공개 호스트 분류 또는 other만 기록한다. 실제 URL·경로·쿼리 값은 기록하지 않는다.
- 태그, 고정 role/itemprop 값, 고정된 의미 있는 클래스 토큰만 기록한다. 임의의 해시 클래스, data-* 값, id, 이벤트 핸들러 코드는 저장하지 않는다.
- 익명 노드 번호와 부모·형제 관계, 이미지/문단/날짜 표시/평점 표시/정렬 컨트롤 개수로 버튼과 표시 영역의 관계를 비교한다.
- selected/expanded는 absent/false/true를 구분한다. 해당 속성이나 CSS 상태 하나만으로 자료를 수집하지 않는다.
- 최대 이미지 24개, 주변 버튼 12개, 노드 프로필 160개로 제한한다. 불러오기에서도 고정 목록과 개수 제한을 다시 적용한다.
- 상품 설명·리뷰 원문·작성자·이메일·전화·로그인 상태·쿠키·비공개 상태·전체 HTML은 진단에 포함하지 않는다. 진단은 사용자 버튼으로만 파일 저장하며 자동 전송하지 않는다.

## Windows 재시험

1. ClipForge를 종료하고 기존 폴더와 data 폴더를 백업한다.
2. 새 브랜치 코드를 기존 파일에 적용한다. 빈 data 폴더를 기존 데이터 위에 덮어쓰지 않는다.
3. `처음 설치하기.cmd`를 실행해 새 코드를 다시 빌드한다. 이후 `쇼핑클립 시작하기.cmd`로 실행한다. 추가 패키지 설치나 새 API 키는 없다.
4. 기존 북마클릿 즐겨찾기를 삭제하고 앱의 `/products/browser` 화면에서 새로 등록한다. 실행 팝업 버전 **2026-10-28.5**를 확인한다.
5. 실제 상품 상단에서 직접 선택하지 않고 실행해 상품명·가격·대표/추가 이미지와 진단 파일을 확인한다.
6. 팝업을 닫고 상세를 직접 펼쳐 상세 이미지/사양이 화면에 보이는 위치에서 실행한다. 자료가 없으면 진단 파일을 별도로 저장한다.
7. 구매평도 직접 열어 본문이 화면에 보이는 위치에서 실행하고 진단 파일을 저장한다. 평점 요약과 전체 리뷰 수만 보이는 화면은 본문 표시 화면과 구분한다.
8. 실패하면 각 화면의 새 진단 파일을 전달한다. 새 imageChecks.reason/host와 neighborhood/nodes로 다음 원인을 좁힐 수 있다. 상품 URL·설명·구매평 원문이 포함되는 상품 자료 JSON 대신 **개인정보 없는 진단 파일**을 전달한다.

현재 페이지 다시 읽기는 새 관찰로 교체하며 화면 간 자료를 자동 누적하지 않는다.
자료 수집과 상업 영상 재사용 권한은 별개다. 기존 시즌 추천·보관함·영상 제작·Windows 실행 코드는 변경하지 않았다.

## 검증 한계

실제 네이버/쿠팡 운영 페이지와 Windows 크롬에서 이번 버전의 성공은 검증하지 못했다.
합성 테스트는 구현 조건을 검증한 결과이며 첨부 상품에서 성공했다는 의미가 아니다.

실행 결과: 148개 테스트 파일 / 1,529개 테스트 통과(이전 버전 대비 25개 추가). TypeScript 검사, 변경 파일 ESLint, 프로덕션 빌드 통과. Chromium 합성 페이지에서 속성 없는 버튼과 표시된 본문으로 상세/리뷰를 자동 수집했으며, 별도 프로덕션 웹앱 제공 북마클릿 3개 합성 사례에서 상품명·가격·대표 이미지·평점·전체 리뷰 수 회귀 및 자료 가져오기 저장을 확인했다. 직접 선택/수정은 0회였다. 실제 네이버/Windows 검증은 아니다.
