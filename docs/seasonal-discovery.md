# 시즌별 상품 발굴

## 화면에서 확인

최신 소스로 실행한 프로그램에서 왼쪽 **상품 발굴**을 선택한다.
모바일에서는 상단 메뉴에서 선택한다. 상품 보관함의 **시즌 상품 발굴** 버튼으로도
들어갈 수 있다. 화면 경로는 `/discover`다. 이미 설치된 Windows 실행 파일은
소스 변경만으로 갱신되지 않으며 이 작업에서 설치 파일을 빌드하지 않았다.

1. **시즌 상품**: 이번 달·다음 달, 이번 달, 다음 달, 2~8주 미리 준비,
   월별 목록 보기와 카테고리 필터를 사용한다.
2. 추천 상품군의 **보관함에서 관련 상품 찾기**를 누른다.
   상품명·설명에 관련 단어가 있는 실제 상품을 찾는다. 다른 표현으로 저장했다면
   검색어를 직접 입력할 수 있다. 의미를 자동 검증한 매칭은 아니다.
3. 실제 상품이 없으면 **상품 링크 추가** 또는 **상품 정보·사진 직접 추가**를 선택한다.
   기존 수집·입력 화면을 사용한다. 종료된 네이버 쇼핑 검색 API를 호출하지 않는다.
4. 사진이 있는 상품에서 **이 상품으로 제작하기**를 선택한다.
   이력을 새로 확인한 뒤, 기존 작업이 있으면 안내창과 기존 프로젝트 링크를 보여 준다.
   의도적인 재제작은 **확인했고 새 영상으로 계속**으로 진행한다.
5. 기존 초보자 제작 화면(`/start?productId=...`) 또는 고급 제작 화면
   (`/project/new?productId=...`)에 상품이 자동 입력된다.

추천 품목을 고르는 것만으로 영상 제작이나 외부 AI 요청을 시작하지 않는다.

## 추천 근거와 일정

`src/lib/seasonal-discovery.ts`는 외부 데이터 조회 없이 작동하는 내부 시즌 기획표다.
한국 시간 `Asia/Seoul`의 실제 날짜를 기준으로 추천하며, 화면을 열어 둔 경우에도
날짜를 갱신한다. 생활용품·주방·가전·육아·인테리어·학습/야외의 30개 상품군을 제공한다.
실제 상품·브랜드·판매량·검색량·추천 순위를 생성하지 않는다.

- 각 품목의 활용 예상 시기에서 56~14일을 뺀 범위를 사전 준비 기간으로 계산한다.
  준비 기간은 편집 기준이며 실제 수요 상승을 입증한 시점이 아니다.
- **2~8주 미리 준비**는 활용 예상 시기의 시작이 오늘에서 14~56일 뒤인 품목만 보여 준다.
- 이번 달·다음 달은 해당 기간에 활용 시기 또는 준비 기간이 겹치는 품목을 보여 준다.
  기본 추천에서는 이미 활용 기간이 끝난 품목을 제외하고, 월별 탐색에서는 과거 월도 볼 수 있다.
- 연말·연초, 겨울의 연도 경계와 윤년 2월을 처리한다.
- 설·추석은 연도별 공식 날짜 데이터가 없어 각각 1~2월·9~10월의 넓은 기획 범위로
  안내한다. 정확한 명절 날짜나 공휴일 캘린더로 표시하지 않는다.
- 수능은 11월 준비 기획이며 공식 시험일·반입 규정을 별도로 확인하도록 안내한다.
- 개학은 학교별 일정을 확인해야 한다. 장마는 통상적인 계절 기획이며 실제 날씨 예보가 아니다.
- 각 카드에 추천 이유·활용/준비 시기·영상 소재·내부 기획표 출처와 기준일을 표시한다.

## 나머지 탭

- **급상승 상품**, **판매 인기 상품**: 데이터 연동 대기. 실제 지표나 순위를 표시하지 않는다.
- **쇼핑클립 추천 상품**: 현재 시즌 조건과 이름·설명에 관련 단어가 있는 보관 상품 후보.
  인기도·종합 점수·자동 제휴 판정은 없다. 사진과 상품 내용을 사용자가 확인한다.

## 제작 이력과 상품 식별

새 로컬 이력 API `GET /api/discovery/history`는 기존 프로젝트·합성 기록만 읽는다.
`done` 합성에 출력 경로가 있을 때 완료 건수로 계산한다. 대기/합성 중·실패·프로젝트만
생성한 상태를 구분하며, `videoCount`나 제작 버튼 클릭을 완료 건수로 세지 않는다.
기존 파일이 삭제된 경우에도 과거 제작 기록은 남으므로 기존 프로젝트 화면에서 파일을 확인한다.

기존 두 제작 화면에서 보관 상품으로 프로젝트를 만들 때만 선택적 `productReference`를
전달한다. 프로젝트 생성 API는 `productId`와 원본 제휴 URL을 저장하고,
기존 SQLite `settings` 테이블의 `discovery:project:{id}` 키에 정규 상품 식별자를
같은 트랜잭션으로 기록한다. 새 테이블·스키마 마이그레이션은 필요 없다.
기존 호출에서 이 값이 없으면 종전과 동일하게 프로젝트를 생성한다.

- 네이버는 호스트·스토어·상품 번호로 구분한다. 추적 매개변수는 식별에서만 제외한다.
- 쿠팡은 상품 번호 기준으로 묶고 다른 옵션도 포함될 수 있음을 안내한다.
- 원본 제휴 URL의 순서·인코딩·추적 정보는 수정하지 않는다.
- 보관함에 같은 상품을 다른 번호로 추가하거나 옛 보관 항목을 삭제해도 정규 식별자가
  있으면 제작 이력을 찾을 수 있다.
- 직접 등록한 상품은 보관함 ID를 사용한다. 서로 다른 ID로 등록한 수동 상품이나
  연결 정보 없는 과거 프로젝트를 이름만으로 같은 상품이라고 단정하지 않는다.
- 이력 조회 오류는 '이력 없음'으로 취급하지 않는다. 다시 확인하기 전 제작 연결을 막는다.
- 이 기능은 중복 안내이며, 여러 창에서 동시에 시작하는 작업을 서버 잠금으로 차단하는 기능은 아니다.

## 제휴 상태

제휴 링크, 스마트스토어 등록 여부, 고지 문구 설정만으로 '제휴 가능'을 표시하지 않는다.
기본은 **미확인**이다. 상품별 **직접 확인한 제휴 상태 기록**에서
브랜드커넥트/쇼핑커넥트 공식 확인 주소와 확인 체크를 입력하면 사용자 확인 날짜와 함께 저장한다.
이는 플랫폼 API가 인증한 상태가 아니며 조건 변경 가능성을 안내한다.
확인일이 미래이거나 출처가 공식 호스트가 아니면 표시하지 않는다.
쿠팡 상품을 네이버 쇼핑커넥트 제휴 가능으로 기록하는 화면은 제공하지 않는다.

## 검증 방법

```bash
pnpm test src/lib/__tests__/seasonal-discovery.test.ts src/lib/__tests__/discovery-history.test.ts --maxWorkers=1 --reporter=verbose
pnpm lint
pnpm build
```

새 테스트는 한국 자정, 연도 경계·윤년, 12개월·카테고리 필터, 2~8주 경계,
불확실한 일정 안내, 상품 매칭·추적 링크 정규화·제휴 근거·실제 SQLite 제작 이력 및
프로젝트/상품 식별자 저장 트랜잭션을 검사한다.
Chromium에서는 별도 테스트 DB로 탭·필터·검색·자료 추가·이력·제휴 기록·중복 안내·
기존 제작 화면 자동 입력·이력 오류·모바일 너비를 확인한다. 실 Windows 실행 파일 검증은 별도다.

2026-10-27 최종 검증: 전체 143개 파일 / 1,413개 테스트 통과(시즌·제작 이력 신규
48개 포함), 프로덕션 빌드·타입 검사 성공, 린트 오류 0개 / 기존 경고 20개.
Chromium 브라우저 13개 흐름을 검증했고 해당 흐름에서 외부 데이터 요청·영상 생성 요청은 없었다.
테스트 DB는 기존 사용자 데이터와 분리했다. 소스 변경은 로컬에만 있으며 이 작업에서
Git 커밋·GitHub 푸시·Windows 설치 파일 배포를 수행하지 않았다.
