# 스마트스토어 상품 가져오기 실패: 진단과 재테스트

이 문서는 이전 v2026-10-28.2 기록이다. 현재 v2026-10-28.3의 자동 추출 변경과 직접 선택 없이 확인하는 절차는 [자동 추출 안내](smartstore-automatic-extraction.md)를 따른다.

대상 제보 주소: https://smartstore.naver.com/sunnycook1/products/11424220493

## 확인한 사실과 확인하지 못한 사실

2026-10-28 이 환경에서 일반 HTTPS 요청을 보냈으나 `CONNECT tunnel failed, response 403`으로 연결 단계에서 실패했다. 네이버의 실제 HTML 응답을 받은 것이 아니므로 네이버 서버가 해당 사용자를 차단했다는 뜻이 아니다. 실제 운영 상품의 클래스·상품 영역·iframe 위치·공개 메타데이터 존재 여부는 **미검증**이다. 이 수정이 해당 상품의 모든 자료를 자동 수집한다고 보장하지 않는다.

기존 코드에서는 URL과 수집 시각을 독립적으로 읽고, 상품 데이터는 `[data-shp-area="top"]` 같은 제한된 선택자만으로 읽었다. 따라서 선택자가 하나도 맞지 않아도 URL·시각만 표시할 수 있었다. 공개 메타데이터 대안, 문서 상태·iframe·선택자 일치 수 진단, 사용자가 영역을 선택하는 방법도 없었다. 이는 소스로 확인한 결함이며, 제보 상품의 실제 선택자 불일치 여부는 진단 결과로 추가 확인해야 한다.

추가 테스트에서 일반 숫자와 상품번호를 전화번호로 잘못 제거할 수 있는 기존 정규식도 발견했다. 국내 전화번호 시작 형식·숫자 경계를 확인하도록 수정했다. 이를 제보 상품에서 모든 항목이 비었던 원인으로 단정하지 않는다.

## 바뀐 수집 방식

- 네이버/쿠팡을 별도 어댑터로 구분하고 기존 상품 전용 DOM 선택자를 유지한다. 실제 확인하지 못한 난독화 클래스 이름을 만들어 넣지 않는다.
- 현재 상품과 일치하는 canonical/og:url 또는 product형 공개 메타데이터가 있으면 `og:title`, 가격 amount/currency, `product:brand`를 참고 후보로 읽는다. 다른 상품/스토어의 canonical을 감지하면 자동 자료를 채택하지 않는다. 메타데이터 값은 선택 옵션의 실제 가격과 같다고 표시하지 않는다.
- DOM 상품명 선택자가 없더라도 현재 페이지의 공개 상품명과 일치하는 main/content 제목 요소는 후보로 읽을 수 있다. 일반 본문이나 document.title 전체를 상품명으로 추정하지 않는다.
- 제품 사양은 기존 상품 상세 범위 또는 현재 상품번호가 일치하는 표의 명시된 사양 항목만 읽는다. 배송/반품 안내 표를 제품 사양으로 취급하지 않는다.
- 이미지는 화면 영역에 있고 CSS로 숨겨지지 않았으며 로드가 완료된 IMG만 사용한다. 상품 이미지 범위나 이 페이지 og:image와 일치하는 IMG에 한정하고, 메타 이미지 URL만으로 사진을 새로 내려받지 않는다. 화면 밖·깨진·미로드 사진은 제외한다. 지원 CDN·HTTPS 제한도 유지한다.
- 구매평은 화면에 보이는 리뷰 본문 전용 요소만 읽는다. 작성자 상자나 전체 페이지 본문을 수집하지 않는다. 반복 본문과 일부 리뷰 작성 안내를 제외하며 실제 구매 인증과 옵션별 일치는 미확인이다.
- URL 중복 이미지 외에 알려진 크기 변환 쿼리 차이도 중복 제거한다. 시각적 유사 이미지/유사 문장 분석은 아니다.
- 공개 DOM·공개 메타데이터·화면 직접 선택·직접 수정·미확인의 출처 방식을 구분한다. 진단값은 관찰 당시 값이며 이후 수정한 자료의 진위나 자동 수집 성공을 인증하지 않는다.

## Windows에서 업데이트 — 즐겨찾기 재등록 필수

이번 수정 브랜치: `fix/smartstore-bookmarklet-diagnostics`.

현재 main에는 시즌 추천·상품 가져오기가 있지만 앞선 Windows 실행기는 아직 별도 브랜치에 있었다. Windows 실행 파일을 빠뜨리지 않도록 `feat/windows-personal-launcher`의 `bb5ac75` 위에 수정했다. 해당 브랜치는 최신 main `89d8655`를 포함한다. 원래 작업 폴더를 덮어쓰지 않았다. PR 비교에는 미병합 Windows 실행기 커밋이 함께 보일 수 있다.

1. 실행 중인 ClipForge 창에서 Ctrl+C로 종료한다. 기존 폴더와 `data`는 삭제하지 않는다. Git을 사용 중이면 로컬 변경·자료를 보존한 채 수정 브랜치로 업데이트하고, ZIP이면 기존 폴더를 통째로 덮어쓰지 말고 별도 폴더에서 시험한다. 다른 폴더의 기존 자료를 사용할 때는 [Windows 실행 안내](../윈도우%20실행%20안내.txt)의 APP_DATA_DIR 안내를 따른다.
2. 소스가 바뀌었으므로 **처음 설치하기.cmd**를 다시 실행하고 완료 후 **쇼핑클립 시작하기.cmd**를 실행한다. 새 ZIP은 https://github.com/omok424642-lgtm/clipforge/archive/refs/heads/fix/smartstore-bookmarklet-diagnostics.zip 에서 받는다.
3. 크롬에서 http://127.0.0.1:3100/products/browser 를 연다. 새 버전 **2026-10-28.2**가 표시되는지 확인한다.
4. 기존 즐겨찾기 ‘상품 가져오기’를 삭제하고 새 화면의 버튼을 다시 즐겨찾기 모음에 끌어 놓는다. 프로그램 업데이트만으로 저장된 북마클릿 코드는 갱신되지 않는다.
5. 테스트 상품을 직접 연다. 기존 수집 창이 있으면 닫는다. 상품 사진·가격이 보이고 로딩이 끝난 뒤 새 즐겨찾기를 실행한다. 확인창에도 **2026-10-28.2**가 표시되어야 한다.

## 진단 화면 읽기

- **문서 loading/interactive**: 문서가 로딩 중이다. 잠시 기다린 후 다시 읽는다. complete도 동적 상품 영역의 완료를 보장하지 않는다.
- **상품명/가격 선택자 일치 0**: 지원 선택자와 DOM 구조가 다르거나 아직 렌더링되지 않았을 수 있다. 공개 메타데이터 후보가 있으면 출처 방식을 확인하고 원본과 비교한다.
- **메타 상품 주소 mismatch**: 주소와 상품 메타데이터가 다르다. SPA 전환 중일 수도 있으니 전환 완료 후 다시 읽거나 탭을 직접 새로고침한다. 다른 상품으로 자동 대체하지 않는다.
- **화면 이미지 > 0, 상품 이미지 0**: 상품 범위나 지원 이미지 호스트와 맞지 않을 수 있다. 상품 사진을 직접 선택하거나 권한 있는 파일을 업로드한다. CSS 배경 사진은 자동 추출하지 않는다.
- **리뷰 후보 0**: 전용 선택자가 안 맞거나 리뷰가 아직 펼쳐지지 않았을 수 있다. 리뷰 탭을 직접 연다. 후보가 있어도 화면 밖·숨김 본문은 제외한다.
- **iframe N개**: 화면에 iframe이 있다는 뜻일 뿐 상품 설명이 그 안에 있다고 확정한 것이 아니다. DOM 접근 가능 수는 내용이 현재 문서에 제공되는지 확인한 결과다. iframe 내부 자료 추출·다른 출처 접근·새 요청·보안 정책 변경은 하지 않는다.
- **접근 제한/보안 확인 문구 감지**: 보이는 제목/안내 문구를 이용한 추정이다. 정상 상품 화면인지 확인하며 제한을 우회하지 않는다.

**현재 페이지 다시 읽기**는 사용자가 누른 시점에만 다시 조사한다. 자동 스크롤·리뷰 페이지 넘기기·반복 API 요청은 없다. 수정한 값이 있으면 교체 전에 확인한다. 선택자·위치가 맞지 않는 경우 아래 직접 선택을 이용한다.

## 화면에서 직접 보완

**화면 글자 직접 선택**을 누르면 아래쪽 도구 막대만 남는다. 항목을 고르고 상품 페이지에서 해당 글자만 마우스로 드래그한 뒤 **선택한 글자 적용**을 누른다. 구매평은 작성자·닉네임·옵션 설명·평점 등을 한꺼번에 선택하지 말고 본문 하나만 선택한다. 페이지 전체·입력창·iframe·숨김/화면 밖 영역은 읽지 않는다. 사이트의 글자 선택 제한을 해제하지 않는다. 적용이 안 되면 자료 제공자의 허락을 받은 내용으로 직접 입력한다.

**화면 이미지 직접 선택**을 누른 뒤 화면에 로드된 실제 상품 사진을 클릭한다. 무관한 추천/리뷰 사진을 선택하지 않는다. 지원하지 않는 호스트·CSS 배경·미로드 이미지·iframe은 가져오지 않는다. 필요하면 사용 권한이 있는 파일을 기존 업로드 기능으로 추가한다. ESC나 확인창으로 돌아가기로 선택을 취소할 수 있다.

상품 주소·쿠팡 옵션 식별자 또는 인식 가능한 선택 옵션이 바뀌면 적용/저장을 막고 다시 읽도록 안내한다. 네이버의 모든 옵션 상태를 자동 검증하는 기능은 아니므로 최종 확인이 필요하다.

## 결과 저장 및 공유

1. **개인정보 없는 진단 파일 저장**은 버전·플랫폼·상품번호·문서/프레임 상태·일치 수·출처 방식만 담은 `clipforge-diagnostic.json`을 저장한다. URL 쿼리, 쿠키, 토큰, DOM HTML, 상품 텍스트, 이미지 URL, 작성자 정보는 담지 않는다. 자동 전송하지 않는다. 사용자가 JSON을 고칠 수 있으므로 진위 인증 자료는 아니다.
2. ClipForge의 상품 가져오기 화면에서 **저장한 진단 파일만 열어 보기**를 펼쳐 이 파일을 로컬로 확인할 수 있다. 서버로 전송하지 않는다. 문제를 전달할 때는 가능하면 상품 자료 전체 대신 이 진단 파일을 제공한다.
3. 실제 상품 자료는 별도로 내용을 검토·수정하고 개인정보를 제거한 뒤 **확인한 자료 파일 저장**을 누른다. 상품 가져오기 화면에서 파일을 열고 정보·이미지 사용 권한을 확인한 뒤 보관함에 저장한다.

자료 수집과 광고/AI 재사용 권한은 별개다. 이 수정은 구매평 AI 분석·영상 다운로드·대본·음성·자막·영상 제작 엔진을 변경하지 않는다.

## 검증 범위

자동 테스트와 Chromium 예제 페이지 검증은 실제 운영 페이지 검증이 아니다. 실제 제보 상품, 다른 네이버·쿠팡 운영 상품, Windows 크롬의 현재 사이트 구조와 글자 선택 동작은 사용자 재테스트 전까지 미검증으로 유지한다.

2026-10-28 최종 결과:

- 전체 **147개 파일 / 1,477개 테스트 통과**. 이번 수정에서 회귀 사례 17개를 추가했다.
- production build·TypeScript 통과. lint 오류 0개, 기존 경고 20개.
- Chromium에서 배포 빌드가 만든 북마클릿(39,324자)을 실제 javascript URL로 실행했다. 예제 네이버 HTML의 공개 메타데이터·현재 표시 제목/이미지·구매평 직접 선택, 쿠키/내부 상태 접근 없음, 진단 파일 저장/로컬 열기, 확인 후 상품 파일 내보내기/가져오기, 권한 있는 이미지 업로드, 보관함 저장, 서버에 저장된 진단/리뷰 다시 열기, 별도 쿠팡 어댑터/리뷰 중복 제거의 9개 흐름을 확인했다.
- 실제 네이버 HTML 대신 **명시적인 예제 응답**을 사용했다. 실제 상품명·가격·이미지·리뷰를 확보했다는 뜻이 아니다. 테스트 자료는 사용자 자료와 분리한 임시 폴더를 사용했다.
- 기존 시즌 추천·보관함 저장 엔진·영상 엔진·프로젝트 생성·Windows 실행기·의존성·DB 스키마는 수정하지 않았다. 이번 수정은 상품 가져오기 화면/계약/북마클릿/진단 표시와 테스트·문서에 한정했다. 기존 원본 작업 폴더도 덮어쓰지 않았다.

기존 설치 폴더에 적용할 때는 먼저 실행 창을 종료하고 폴더를 백업한다. 이번 작업의 업데이트 ZIP은 수정된 `src`/`docs` 파일만 포함하며 `data`, `.env`, `node_modules`, 기존 실행 파일은 포함하지 않는다. 직접 코드를 수정한 PC에서는 해당 수정과 비교한 뒤 적용한다. 새 설치용 전체 ZIP과 업데이트 ZIP을 혼동하지 않는다.
